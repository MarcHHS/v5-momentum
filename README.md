# v5 动量回调体系

A 股主板的**回调买入信号系统**。核心不是预测涨跌，而是给一个可以执行、可以止损、
可以复盘的动作：在上升趋势的回调末端，用结构确认位当买点，用结构失效位当止损，
并且要求盈亏比至少 2:1 才允许出手。

> 本项目是研究与工程实现，不是投资建议。作者不对任何使用结果负责。

---

## 一、这套东西在解决什么问题

动量策略最容易犯两个错：

1. **追高**——看到涨得好就买在最高点，回调一来就被套
2. **抄底**——看到跌得多就买，结果是下跌中继

v5 的做法是：**等趋势中的回调结束、并重新向上确认**。
所以它的买点永远在「回调低点」的上方，而不是低点本身。

这带来一个反直觉但关键的性质：**买区永远在止损上方**。
买在结构确认的位置，止损放在结构失效的位置，中间那段差价就是这笔交易承担的风险。

## 二、策略定义

### 2.1 五道资格关（趋势必须成立）

| 条件 | 含义 |
|---|---|
| 收盘价 > EMA50 | 中期趋势向上 |
| EMA50 五日上行 | 中期趋势还在加强 |
| EMA21 五日上行 | 短期趋势还在加强 |
| EMA9 > EMA21 | 短期强于中期 |
| 20 日均成交额 ≥ 门槛 | 有资金关注，不是死水 |

均额门槛按市值分档：**≤500 亿→2 亿，500~2000 亿→4 亿，>2000 亿→6 亿**。

### 2.2 找止跌K（回调结束的证据）

在最近 20 根 K 线里，从最新的往前找，第一个满足下列形态之一、且**之后所有收盘都没跌破它的最低价**的 K 线：

- **锤子线**：下影线 ≥ 实体 2 倍，上影线 ≤ 实体
- **看涨吞没**：今日阳线实体完全包住昨日阴线实体
- **缩量阳**：连续两根阴线且第二根缩量，今日收阳

找到后，它的**最高价 = P**，这是买区下沿，也是「结构确认位」。

### 2.3 算目标 T

```
Hh = 止跌K之前 60 根内的最高价
Ll = Hh 所在那根往前 20 根的最低价（起涨点）
T  = min(Hh, P + (P − Ll))
```

取「前高」与「等幅投影」中较近的那个。T **不用于止盈**，只用于反解买区上沿。

### 2.4 定止损 S

五个候选位：5 日低、10 日低、20 日低、布林下轨、MA21。

合法的条件是同时满足：

```
P − S ≥ 1.0 × ATR14      （太近会被日常波动扫掉）
P − S ≤ 2.0 × ATR14      （太远则单笔风险失控）
P − S ≤ 8% × P
```

在所有合法候选里取**最高**的那个。再检查止损宽度：

```
(P − S) / P ≤ 4.5%
```

超过就放弃这个信号——说明买点离支撑太远。

### 2.5 算买区上沿 e_max

```
e_max = min( (T + 2S) / 3 ,  P × 1.05 )
```

第一项是**盈亏比恰好为 2 的价位**：

```
R = (T − e) / (e − S) = 2   =>   e = (T + 2S) / 3
```

第二项是追高刹车：买入价不得高于止跌K高点 5%。

**买区 = [P, e_max]，下沿是 P，上沿是 e_max。**

如果算出 `e_max < P`，说明在 P 这个价位盈亏比到不了 2，**买区不存在**，
这个信号直接作废。这种情况在实盘里出现得很多，不是异常。

### 2.6 缩量确认

```
pbr = 回调期均成交量 ÷ 上涨末段均成交量
回调期   = 前高次日 ~ 止跌K
上涨末段 = 前高及之前 19 根
```

| pbr | 判定 |
|---|---|
| ≤ 0.75 | A 档，标准合格 |
| 0.75 ~ 0.80 | B 档，边界合格 |
| > 0.80 | 不合格 |

### 2.7 出场

只有两条，**没有固定止盈**：

1. **固定止损 S**——买入时定死，永不下移
2. **吊灯止损**——`max(持仓期最高价 − 4 × ATR14, S)`，只上移不下移

也就是说：赚钱了就让吊灯跟着抬，不主动卖；亏钱了碰 S 就走。

## 三、数据口径

这一节是本文档最重要的部分。改任何一行代码前请先读这里。

### 3.1 市场范围

- **A 股主板**：沪市 `600 / 601 / 603 / 605`，深市 `000 / 001 / 002 / 003`
- **不含**：创业板（300 / 301）、科创板（688）、北交所（bj）

代码前缀直接过滤，见 `v5/config.py: BOARD_PREFIXES`。

### 3.2 K 线频率

**日线。一根 = 一个交易日。** 不做分钟级、不做周线、不做复权后重采样。

### 3.3 复权方式

**前复权（qfq）。**

这一点不能含糊：止损位、止跌K高低点、均线、布林带全都在同一条前复权序列上计算。
如果临时降级到不复权数据源，历史价位会和判定口径错位，**必须显式标注**，
不允许闷着用。

代码里 `data.kline()` 返回第三个值 `adjusted`，为 `False` 表示走的是不复权兜底源。

### 3.4 数据来源与降级顺序

| 顺序 | 来源 | 接口 | 复权 | 备注 |
|---|---|---|---|---|
| 1 | 腾讯财经 | `proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get` | 前复权 | 历史约 640 根上限，带成交额字段 |
| 2 | 东方财富 | `push2his.eastmoney.com/api/qt/stock/kline/get`（`fqt=1`） | 前复权 | 兜底 |
| 3 | 新浪财经 | `money.finance.sina.com.cn/.../CN_MarketData.getKLineData` | **不复权** | 最后兜底，会打标记 |

开跑前会先探一次源（`data.detect_source()`），避免几千只股票逐个去撞已经挂掉的接口。

**公开接口没有 key、没有配额保证**，随时可能限流或变更字段。所有请求都带重试
（默认 3 次，退避 0.5s / 1.0s / 1.5s）。

### 3.5 字段与单位

所有 K 线统一转成同一种结构：

```
[日期, 开盘, 收盘, 最高, 最低, 成交量(股), 成交额(元)]
```

- 腾讯：成交量原始单位是「手」，×100 转「股」；成交额第 9 位单位是「万元」，×1e4 转「元」
- 东财：成交量 f56 单位是「手」，×100 转「股」；成交额 f57 单位是「元」
- 新浪：成交量已是「股」

实时快照（`qt.gtimg.cn`）字段：

| 字段位 | 含义 | 内部单位 |
|---|---|---|
| f[1] | 名称 | — |
| f[3] / f[4] | 现价 / 昨收 | 元 |
| f[32] | 涨跌幅 | % |
| f[33] / f[34] | 最高 / 最低 | 元 |
| f[36] | 成交量 | 手 |
| f[37] | 成交额 | 万元 → 内部转亿元 |
| f[45] | 总市值 | 亿元 |
| f[49] | 量比 | — |
| f[51] | 均价 | 元 |

每批 30 个代码一次请求（`config.QUOTE_BATCH`）。

### 3.6 时区与「今天」

全部按**本机本地日期**判断，默认假设在 Asia/Shanghai。

盘中（09:30–15:00）取历史 K 时会**剔除数据源返回的当日未完成 K 线**，
再用实时快照拼一根合成 K。原因是半根 K 进结构计算会让信号在盘中反复出现又消失。

于是产生一个必须记住的规则：

| 时段 | 结构确认基准 |
|---|---|
| 盘中 | 倒数第二根（昨日收盘） |
| 收盘后 | 最后一根（今日收盘） |

「距买区 %」永远用实时价算：正数 = 还要涨才到 P，负数 = 已越过上沿。

### 3.7 股票池

`scripts/fetch_history.py` 从东方财富 `push2.eastmoney.com/api/qt/clist/get` 拉列表，
参数 `fs=m:1+t:2,m:1+t:23,m:0+t:6,m:0+t:80`（沪深主板），然后：

- 排除无价 / 无市值（停牌）
- 排除名称含「退」或以「PT」开头（退市）
- 按前缀二次过滤，确保只有主板

### 3.8 财报数据

东方财富 `datacenter-web.eastmoney.com`。

| 用途 | reportName | 口径 |
|---|---|---|
| 单季利润表 | `RPT_F10_FINANCE_GINCOMEQC` | 单季 |
| 银行/保险兜底 | `RPT_LICO_FN_CPD` | **累计**，结果里会带 `cum_only=True` |
| 经营现金流 | `RPT_F10_FINANCE_GCASHFLOW` | 累计 |

取四个数：单季营收同比、单季归母同比、毛利率同比（百分点差）、经营现金流。

**财报只作补充信息，不参与任何判定。** 这一点在代码层面保证：
`signal.py` 完全不接触财报字段。

### 3.9 数据缓存

- `data/kcache/<日期>/<代码>.json`——当日历史 K 线缓存，跨日自动失效
- `data/history.jsonl`——一次性抓的全市场历史，回测用

想强制刷新就删掉对应目录。

## 四、安装与运行

纯标准库，**没有任何第三方依赖**。Python 3.9+。

```bash
git clone <repo>
cd v5-momentum

# 1) 先抓历史数据（约 3000 只，几分钟，落盘约 300MB）
python3 scripts/fetch_history.py

# 2) 回测
python3 scripts/run_backtest.py --start 2024-01-01

# 3) 看今天有没有信号
python3 scripts/scan_today.py

# 或者只查指定几只
python3 scripts/scan_today.py --codes sz002044,sh600809
```

先小样本试跑：

```bash
python3 scripts/fetch_history.py --limit 30
python3 scripts/run_backtest.py --limit 30 --start 2025-01-01
```

`data/` 目录不进版本库——全市场历史约 300MB，超过 GitHub 单文件 100MB 限制。

## 五、输出怎么读

`scan_today.py` 只把**除价格外全部条件成立**的标的拿出来分三段：

| 段 | 含义 | 该做什么 |
|---|---|---|
| 第 1 段 | 现价已在买区内 | 理论上可以挂单 |
| 第 2 段 | 还没涨到 P | 等它涨到 P |
| 第 3 段 | 已越过 e_max | 涨过头了，等回落 |

剩下那些不满足条件的，只给一个**原因分布**，不逐只列。
因为「差一条」和「可以买」是两件事，混在一起看必然误判。

漏斗会打印：全市场 → 有结构 → 除价格外全过 → 价格在区内。
正常情况下最后一级经常是 **0**。这不是系统坏了，是条件本来就严。

## 七、已知问题与设计取舍

### 7.1 已修复：止跌K「当日自证」

旧实现的止跌K搜索是从 `j = t` 开始的，而验证条件是

```python
all(c[k] >= l[j] for k in range(j + 1, t + 1))
```

当 `j == t` 时 `range(t+1, t+1)` 是空集合，`all([])` 恒为 `True`。
结果就是**当日 K 线自己证明自己是止跌K**，而「之后没有破底」这件事从来没有被验证过。

修复方式是要求 `j < t`，即止跌K之后至少有一根 K 线来验证。

**这个 bug 的影响不小。** 用 300 只主板股票、2018-06 起的 601,903 个判定时点做审计
（`scripts/audit_selfnode.py` 可复现）：

| 项目 | 数量 | 占比 |
|---|---|---|
| 止跌K落在当日的时点（旧实现会采纳） | 113,806 | 全部时点的 18.9% |
| 买区成立：旧口径 | 56,408 | 全部时点的 9.4% |
| 买区成立：修复后 | 53,898 | 全部时点的 9.0% |
| **只有旧口径才成立（虚假信号）** | 7,234 | 旧口径的 **12.8%** |
| 两口径都成立但 P 变了（买区整体平移） | 5,275 | 修复后的 9.8% |

也就是说，旧实现给出的买区里，**约八分之一根本不存在**，另有约十分之一的
P 算在了错误的止跌K上，上下沿跟着整体偏移。

一个真实例子：某只股票在新旧实现下分别给出「买区 50.55~50.79，距买区 +0.58%」
和「买区倒挂，作废」两种完全相反的结论——差别只在于旧实现把昨天的锤子线
当成了止跌K，而那根锤子线之后一根 K 都没有。

### 7.2 设计取舍

**前复权会随分红变化。** 前复权序列里，除权日之前的历史价位会被按比例调整。
所以用几年前的信号回测时，当时看到的价格和今天看到的数字不一样。
判定在逻辑上不受影响（都在同一条序列上），但绝对值不能跨时间对比。

**不含涨跌停与停牌。** 开盘一字涨停买不进、跌停卖不出的情况没有建模。

**不含交易成本。** 佣金、印花税、滑点都不在本模块。回测结果是单笔等权平均收益，
不是账户净值曲线。

**财报是补充信息，不是筛选条件。** 一只票技术面合格但财报难看，仍然会出现在名单里，
只是会带一个提示。这个设计是刻意的——财报滞后于价格，用它做否决会错过反转。

## 八、样本结果

以下是一组小样本（主板前 300 只，2024-01 起，止损宽 4.5%、4ATR 吊灯、无固定止盈、
未加市值与波动率过滤）的结果，用来说明代码能产出什么，**不代表策略在所有市况下的表现**：

```
成交 70 笔   笔均 +1.88%   中位 -2.86%   胜率 29%
平均 0.8 R   平均持有 15.9 天   盈亏比 1.83
离场：止损 47 笔 -3.34% / 吊灯 22 笔 +12.97%
```

这个结构很典型：**胜率不到三成，靠少数几笔大盈利把总账拉正**。
如果你的心理预期是高胜率，这套体系会让你很难受。
